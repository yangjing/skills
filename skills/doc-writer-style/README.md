# doc-writer-style

按 yangjing 的既有风格撰写中文技术博客：问题驱动、第一人称经验流、具体细节，并系统性规避 AI 味。

## 简介

基于 15 年博客写作经验（2010-2026，140+ 篇已发布文章）总结的中文博客写作风格 skill。覆盖技术教程、架构设计、经验分享、技术选型、随笔、翻译六类文章，每类有对应的结构模式（如教程的「背景 → 环境准备 → 核心实现 → 运行测试 → 常见问题 → 小结」）。

三条核心风格：

- **问题驱动，直接开头**：开头一至三句话进入正题，不做宏观铺垫，不加"前言"章节。
- **第一人称经验流，有态度**："我"高频出现，直接下判断，敢表达个人偏好，不追求面面俱到。
- **具体，有细节**：多给版本号、耗时、页数、命令输出等真实数字；官方文档能查到的给链接、不复述。

另含一份**AI 味检查清单**：按开头 / 用词 / 句式 / 结构节奏 / 中文特有句式 / 结尾 / 格式 / 内容逐类给出坏例与替换方案，并标注误伤边界（否定对比、流程连接词等有真实功能的表达保留），判断方法吸纳自 stop-slop-zh、Humanizer-zh 等项目并与本博客历史风格融合。

## 站点约定（overlay 机制）

frontmatter、文件名、分类标签等站点特定约定是**可选特性**，按优先级取：

1. **站点 overlay**：项目内的 `doc-writer-style.overlay.md`，可覆盖本 skill 的任何默认约定
2. **Hexo 通用参考**：确认是 Hexo 站点且无 overlay 时，读 `references/hexo-frontmatter.md`
3. 都没有时沿用目标站点已有文章的格式；仍无法判断则问用户，不猜测

## 安装

```bash
# 安装到当前项目
npx skills add <owner>/my-skills --skill doc-writer-style

# 全局安装
npx skills add <owner>/my-skills --skill doc-writer-style -g -y
```

## 使用说明

本 skill 面向 AI Agent 自动执行。用户提到写文章、写篇博客、记录经验或踩坑、发教程、润色或检查已有文章风格（含英文请求 write a blog post / tutorial）时触发。

写作流程：判断文章类型 → 收集真实素材（没有的不编造）→ 按对应结构模式起草 → 逐条过 AI 味检查清单修订 → 按 overlay 或 Hexo 参考写元数据。交付前有一份自查清单（开头是否三句入题、段落是否够短、代码块是否标语言、链接是否真实存在等）。
